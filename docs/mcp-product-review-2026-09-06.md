## 产品判断

最严重的问题是执行结果与完成承诺脱节，其次是把 SDK 兼容性和恢复工作推给模型。增加更多状态、预览和确认步骤会继续拉长调用链；应让工具直接完成正常操作，失败时只给原因和可执行的下一步。

历史模型关于“原生导线没有写入”“唯一阻塞原因”等叙述并不都可靠。STM32 后续还清理了临时短线，因此本次不把空返回等同于没有副作用，也不把模型自己的根因断言当作已证实事实。

## 改动边界

- 正常调用直接执行；工具内部做必要检查和回读。dryRun 保留为可选预览/调试方式。
- 批量仅添加 `remainingIndices`（本次输入、从 0 开始），包含失败/未确认及尚未执行项。已有失败结果的项先回读再续做，不重放成功项。
- 碰撞时额外返回 `suggestedPosition`，依据当前障碍向右寻找候选位置；后续仍需工具检查，不承诺排版美观。
- NET 默认使用原生 `sch_PrimitiveWire.create(line, netName, ...)`。同名符号端点重叠仍需导线连接，不能跳过；可选符号外移到引线末端。内部核对实际端点和网表，只有目标器件 ID、引脚号和网名相符才成功。
- component_place 接受 nets 映射，先放置全部器件再连接，连接失败保留放置结果。兼容性错误直接给 Escape Hatch，不轮流试写多个包装器。
- 后台连接增加原生 WebSocket ping/pong；页面计时器暂停恢复后获得新的 ACK 窗口。传输层需要重装插件，宿主彻底冻结时仍不能执行任务。
- 当前每批最多 50 个引脚，先用精确点线相交及包围盒检测；暂不引入 R-Tree/四叉树。空间索引仅能加速候选筛选，不能证明电气连接；待大图性能数据证明需要时再加。
- 严格 DRC 可能提示闲置 GPIO；应核对设计意图与未连接标记，不能忽略所有未连引脚。
- 网表 warnings 是可见证据缺口；没有 warnings 也不证明目标连接全部正确。

尚未完成：完整 STM32 图修复与美观排版、完整设计目标网表比对、跨重启幂等恢复、完整 PCB 生成及最小化场景的新版插件实机验收。独立端口为何未触发宿主连接仍属 SDK 行为问题，但已验证真实命名导线可建立连接。历史提交 611e3f1/d05aec2 的保存提示变化不是功能修复；本轮保存实验未修复空网。本次只自动编号新建元件，原图旧元件与符号保持原样。

## 实机验收标准

本轮隔离页实测：两个原生命名导线引脚导出 MCP_LAB_WIRE；组合 Facade 新放置 R3 并连接 MCP_FACADE_TEST，首次立即导出尚未确认，后续严格审查导出正确网名。已加入导出前严格 DRC 刷新，刷新是否完全消除时序问题仍需复测，不自动重试写入。测试页 bf9ffcfa8f7e4b92 及其测试元件/导线已删除，确认原 P1 f2151c03f53ba786 保留。未修复原 STM32 图中的历史重叠符号。

在专用测试图页执行真实的“两器件放置 → 同名 NET 创建 → 导出网表确认两个端点同网 → 重复调用无重复 NET → 清理测试对象”。再覆盖缺失 BBox、批量第二项碰撞、页面切换与断线。记录真实写入成功率、达到目标的调用次数、重复对象数及人工干预次数。

STM32 验收需明确具体后缀/封装，以真实库引脚核对电源、去耦、复位、启动、时钟和 SWD；原理图与 PCB 分别验收。不得再使用“NET dry-run 成功”替代真实连网验收。
