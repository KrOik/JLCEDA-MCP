# 分类行包装器：实测后的方案 v2

更新：分类行实现已接入 1.6.0，后续原生试验已完成。当前实现、验收和仍有的限制见 [发布说明](../../docs/type-rows-1.6.0.md)。下文保留当时的实验设计及故障记录，不代表当前上线状态。

2026-09-07。目标是让 Agent 提交器件及网络映射后，由确定性代码完成排版、引线和回读。这里交付实验原型及设计，不是已上线的新 MCP 工具。

## 结论

采用“分类行 + 独立器件单元 + 属性标题区 + 有序正交扇出 + 外侧网名区”。单纯将器件按类别分行不够。布局和原生 SDK 执行必须分层：布局可以确定性计算，但创建器件、网名显示、跨页连网与超时恢复都要单独验收。

## 实测证据

只读采集原 P1 的 15 个物理器件、89 个真实引脚、21 个非空可见属性边界和 103 条导线，原始数据见 live-fixture.json。

- STM32：本体约 151 × 251；包含引脚及可见属性后约 170 × 268；两侧引脚间距 10。
- U3 实际是 Micro-USB 母座；有下方 5 个引脚和左右各 1 个引脚。只凭 U 前缀分类会出错。
- C1、C4、R2、X1 当前为纵向两端引脚；几何原型将这四个符号旋转为横向。生产实现必须在旋转新实例后重新测量，不能假定所有库内文字都按矩阵旋转。
- 属性 getter 与 BBox 的 Y 符号不同。例如 U1 位号 getter 的 y=-540，实测 BBox 的 y=540..548。不能混用属性坐标和原理图世界坐标。
- 103 条导线里有 57 条不经过当前器件集的联合边界，包含约 x=19615、y=-60645 的历史导线。不能将全页最小 Y 直接当作新增排版起点；这项统计不等于确认全部为可删除孤线。
- 实际导出网表中只有 47 个引脚带非空网名；DRC 未通过。原型复用这些映射用于布局基准，不把原电路当作正确最小系统，也不替未连接引脚猜网名或补 NC。
- 103 个导线 BBox 都仅覆盖线段及约 0.5 的线宽边界，没有覆盖屏幕上显示的网名；前 12 条导线关联属性查询没有得到可见 NET 字框。网名不能用 Wire BBox 做视觉验收。
- schematic_read.geometry.ports 经当前四层序列化被替换为 MaxDepthExceeded；实验通过逐器件的 getAllPinsByPrimitiveId 读取了真实引脚。正式包装器在 Bridge 内部规划，返回外部的几何证据使用扁平 pin 表或分块结果。

## 可复现实验

运行 `node experiments/type-rows/run.mjs`，无需连接 EDA。交互式预览见 preview.html，可切换排版方案、字体高度、行宽及全部引脚长网名压力场景。

三种方案都使用相同的实测符号、引脚和可见属性数据。网名字框是保守的参数模型（ASCII 宽 0.65 × 字高/字，非 ASCII 宽 1 × 字高/字），不是 SDK 测得的真实字体边界。

默认字高 10、行宽 1200、当前 47 个带网名引脚：

| 方案 | 模型冲突对数 | 范围（原生单位） | 说明 |
|---|---:|---:|---|
| 仅分类行，按裸器件占位 | 39 | 534 × 826 | 引线/文字侵入邻居及自身属性 |
| 完整单元占位，保持原属性和直引线 | 31 | 771 × 996 | 单元之间已分离，但单元内部仍冲突 |
| 标题区 + 水平两脚器件 + 有序扇出 + 外侧字框 | 0 | 1061 × 960 | 所测试几何模型中无冲突 |

“冲突对数”可能有同一区域多类冲突，不是独立 DRC 错误数。

- 改进方案通过 24 组检查：字高 8/10/12/16 × 行宽 800/1200/2000 × 当前网络/全部 89 引脚长网名。
- 另通过 100 组固定随机种子的稀疏引脚子集检查。这个测试很重要：只有少数不连续引脚接线时，简单均匀展开后再整体居中会产生交叉。
- 验证内容：器件单元间重叠、导线交叉、导线穿本体/其他引脚/字框、文字重叠或覆盖本体，以及确定性、有限正交坐标、引线起点和引脚网络映射保持。
- 增加分页试算：行宽 1000、A4 可用区假设 1050 × 700 时，当前样例分为两页，内容高度分别 689 与 297；电容有续行。可用区需在生产实现中读取图框/标题栏后确定。
- 没有宣称任意符号、任意字体或四边角部引脚都已验证。无原生文字测量时必须返回 `textGeometryVerified=false`。

## 原生临时页实验及未完成项

临时页 `ROWS_LAYOUT_PROBE`，UUID `65f0708b2a9413dc`，创建于同一原理图内；没有修改 P1 中的器件或导线。

原计划创建一个 U901，比较：①整条折线赋网名；②内部线段无网名，只给最外侧直线段赋网名，随后比较原生显示与实际网表。

实际结果：创建页面会异步激活新页，但 Bridge 上下文更新稍晚，紧接着 document_focus 返回 DOCUMENT_CHANGED。回读确认新页后继续；component_place 随后持续不返回。客户端 60 秒超时，服务端之后将请求 `bridge_req_1788751736602_332` 标记 EXECUTION_UNCERTAIN，并拒绝新任务，连只读回查与清理也无法执行。

因此该原生连线实验未执行到连线/网表验收阶段。未重试器件创建。journal 已标记 placement-uncertain；不能因为 createdIds=[] 就认为器件肯定没有创建。native-probe.png 是当时 EDA 窗口截图，只能证明当前视窗内没看到器件，不能证明远处暂存区为空。

临时页尚未清理；恢复 Bridge 的执行能力并核实旧调用已停止后，执行 `node experiments/type-rows/native-probe.mjs cleanup` 可按记录的 UUID 删除测试页并返回 P1。脚本先核对所属原理图、精确 UUID 和测试页名称；不会删除原页面。当前不能声称原生方案验收通过。

## 包装器接口

对 Agent 暴露一个主入口，默认直接执行；预览是可选模式，不强制引入人工批准环节。

```json
{
  "tool": "schematic_place_rows",
  "operationId": "stm32-minimum-v1",
  "pagePolicy": "new-managed-pages",
  "preset": "type-rows",
  "components": [
    {
      "key": "reset-pullup",
      "candidateRef": "真实候选引用",
      "designator": "R1",
      "row": "resistor",
      "nets": {"1": "+3V3", "2": "NRST"}
    }
  ]
}
```

坐标、间距、扇出深度不要求 Agent 提供。高级参数置于 profile 中，使用经过验证的默认值。`operationId + key` 负责幂等与恢复；请求内容哈希不同而 operationId 相同时返回冲突，不能重放创建。

类别顺序固定：switch → capacitor → crystal → resistor（含电感）→ connector → ic → other。分类优先级为显式 row、器件库的可靠类别、名称/封装组合、位号；不确定则 other。实例位号不随类别改变：U3 仍叫 U3，但进入 connector 行。

## 确定性排版规则

1. 两引脚且方向相对的 R/C/L/X 使用水平模板；有极性器件保持引脚号/极性，不靠外观交换网络。多引脚晶振、开关、接口和 IC 保留正常符号方向，按实际引脚侧布局。
2. 每个单元分为标题区、符号区、扇出区、网名区。位号与可见名称移到标题区，名称不覆盖引线。保留型号全文，允许扩大标题区，不擅自删掉型号。
3. 对每一侧的接线引脚按真实坐标排序。从中位引脚向两端展开，目标间距至少 ceil((字高 + 6)/10) × 10，原来较大的间距保留。字高 10 时为 20。
4. 外侧引脚先折弯、内侧引脚后折弯；不能所有引脚共用一个折弯 X/Y，否则会发生重叠/交叉。网名区必须在所有折弯点之外，包括没有偏移的中间直引线。
5. 网络命名由调用方确定。包装器只生成同名命名连接，不擅自连接不同网名、不把未知引脚设为 NC，不按位号猜开关内部等效触点。
6. 将整个单元按自然位号顺序排入分类行；从左到右放置，下一行向屏幕下方推进。统一在布局内部使用 Y 向下坐标，最终写入由单一适配器转换回 EDA Y 向上；属性 API 单独适配并回读。
7. 超出可用行宽时同类别续行；超出页高时换到托管新页，不缩小字体。单个单元超大时使用更大图框或明确返回 PAGE_TOO_SMALL，不无限外移。
8. 对已有页追加，只在明确的局部可用区域做有限检测；默认新设计使用托管新页。历史远处导线不推动全局起点，也不自动删除。

## 原生 NET 实现选择与验收门槛

优先验证“无名内部折线 + 命名外侧直线段”。其优势是将自动显示的网名限制在可预留的直线段，但目前只是候选方案，尚未通过本次实机实验。

必须验证：无名线段是否在 DRC/保存后获得并显示网名；多段线之间是否按真实端点电气连通；不同页面同名网络的作用域；长网名及竖向网名是否仍在预留区；重复 NET 标签是否造成显示冗余。

若原生 Wire 自动文字不可控制，则评估明确的原生 NetLabel/NetPort 能力，但不能把可见文字当成连接证明。历史记录中 NetPort 曾出现“对象创建成功但网表为空”，需要单独验证。不要通过新增一层普通 Text 假装解决 NET 问题。

在上述门槛通过前，仅可开放几何预览，不把该路径设为生产默认。

## 分阶段执行与恢复

状态机：validate → resolve → create/probe → measure → plan → place → wire → verify → done。每一步记录请求意图、当前页面、已知图元 ID、输入哈希和回读状态。

- 页面创建后等待原生当前页与 Bridge context 都匹配，不把暂时的 DOCUMENT_CHANGED 当成必须用户处理的问题。
- MCP 短请求返回 jobId；Agent 通过 status/resume 获取进度，避免一次工具调用承载全板。Bridge 保留任务所有权，不能因客户端断线再次创建。
- 创建、属性更新和导线写入均保留逐项完成记录。最多 50 项的现有包装器限制应由内部拆批承担；全部 89 引脚压力样例不能要求 Agent 自己拆分。
- 单项超时标记 uncertain，禁止盲重试。状态查询和受限制的只读诊断应独立于写队列，但不能把“读得到页面”当作原调用已经停止。
- 只有明确取消确认、原调用完成并回读，或受控重载后核实迟到写入，才允许恢复写任务。单纯增加 Promise.race 超时不足以取消 SDK 的迟到写入。
- 清理只涉及本 job 记录的临时资源；新建托管页可以成为隔离边界，原用户页面不做自动回滚。无法确认的创建必须报告并保留证据。
- 同页只读验收与全工程网表/DRC 范围分开，已有 P1 的 DRC 错误不能被归因到新布局任务，也不能被隐藏。

推荐返回：

```json
{
  "jobId": "rows-job-...",
  "state": "verify",
  "progress": {"componentsPlaced": 15, "pinsRequested": 47, "pinsConfirmed": 47},
  "verification": {
    "placementConfirmed": true,
    "connectionsConfirmed": true,
    "geometryModelPassed": true,
    "textGeometryVerified": false,
    "nativeRenderVerified": false,
    "drcCheckPassed": false
  },
  "remainingKeys": [],
  "uncertainPrimitiveIds": []
}
```

这只是字段示例，不是本次线上执行结果。只在全部请求项及所选验收条件满足时 state=done；阶段成功不能概括为电路完成。

## 实现优先级

P0：先解除“SDK 长调用锁死整个 Bridge”的恢复能力缺口；原生文字与分段线网表小样验收。

P1：将已验证的纯布局器接入 Bridge；实现真实旋转后测量、标题区属性回读、模板化命名引线、分页和幂等 journal。复用现有位号分配、实测 BBox 和连接验证，不再复用局部螺旋避障作为默认布局方式。

P2：新增器件类别和极端符号；跨页标签作用域验证；覆盖保存/重新打开、部分失败恢复、重复 operationId、迟到写入和用户并发修改的实机回归。
